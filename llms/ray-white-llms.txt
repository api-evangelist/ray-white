# Ray White

> Ray White is Australasia's largest real estate group — a family-owned brokerage
> network founded in Brisbane in 1902, running 550+ Australian offices and roughly
> a thousand offices across Australia, New Zealand, Indonesia, Hong Kong, China,
> Papua New Guinea, the Middle East and Atlanta USA. It publishes NO public API.
> Ray White is an API CONSUMER: in December 2025 it named realestate.com.au and
> PropTrack (REA Group) its data partners explicitly for their "industry leading
> API architecture", piping that licensed market data into its proprietary
> OneSystem, NurtureCloud and Pulse platforms. There is no developer portal, no
> API documentation, no OpenAPI/OData/GraphQL/AsyncAPI contract, no SDK, no
> Postman collection and no partner-API application path. RESO is absent — Ray
> White does not appear in the RESO certification directory, which is expected for
> an Australian brokerage (Australia has no MLS/NAR system; the closest required
> machine-readable rail is PEXA electronic conveyancing, which Ray White transacts
> through as a participant rather than exposes).

## API surface

- [API posture: none published](https://github.com/api-evangelist/ray-white/blob/main/review.yml): No OpenAPI, OData $metadata, GraphQL, AsyncAPI, webhooks, SDKs or Postman collection. Four developer subdomains (developer/developers/api/docs.raywhite.com) do not resolve; the site sitemap contains no developer, api, docs, integration or partner section.
- [Access gate: none-published](https://github.com/api-evangelist/ray-white/blob/main/review.yml): No developer programme, no partner-API application form, no API terms and no data-licence page. The only evidenced route to Ray White data is a bilateral commercial agreement, of the kind Ray White itself struck with REA Group/PropTrack.
